# 온라인MBTI

카카오톡 오픈채팅·1:1 DM·단체톡 대화 내용을 붙여넣거나 `.txt` 파일로 끌어다 놓으면,
대화에 등장하는 **사람마다 MBTI를 추정**해서 탭으로 보여주는 웹 앱입니다.

판정은 **Command Code Provider API** 로 실시간 AI가 수행합니다.

## 실행

Node.js 20.6 이상만 있으면 됩니다. 설치할 패키지가 없습니다.

```bash
npm start
```

브라우저에서 http://localhost:3000 을 엽니다.

## 사용 순서

한 번에 전부 판정하지 않고 **세 단계**로 나눠서 처리합니다.
등장인물이 많아도 요청 하나가 작아서 실패가 적고, 중간 진행 상황이 보입니다.

1. **1단계 · 등장인물 찾기** — 대화에서 화자 목록만 뽑습니다 (5초 내외).
   이름, 발화 수, 대화에서의 역할이 나옵니다.
2. **2단계 · 판독할 사람 선택** — 체크박스로 고릅니다. 기본은 전체 선택이고,
   필요 없는 사람(짧게 지나가는 사람 등)은 빼면 시간이 절약됩니다.
3. **3단계 · 한 명씩 순차 판독** — 체크한 사람을 **한 명씩 순서대로** 판정합니다.
   진행 목록에 `대기 → 판독 중 → 완료 / 실패` 상태와 경과 시간이 표시되고,
   끝난 사람부터 결과 탭이 쌓입니다. 한 명이 실패해도 나머지는 계속 진행됩니다.

> 처음에는 전체를 한 번에 판정했는데, 출력이 커지면서 응답이 120초를 넘겨
> 게이트웨이 타임아웃(524)으로 실패했습니다. 그래서 사람 단위로 쪼갰습니다.

## API 키

`.env` 파일에 Command Code API 키를 넣습니다. (이미 발급받은 키가 들어 있습니다.)

```
COMMANDCODE_API_KEY=user_...
PORT=3000
```

키는 **서버에서만** 사용되고 브라우저로 전송되지 않습니다.
키를 바꾸려면 `.env` 를 고치고 서버를 다시 시작하거나, 화면의 **고급 설정 → API 키 재정의**에
그때만 쓸 키를 넣으면 됩니다(저장되지 않음).

> Go 플랜은 API 접근이 없습니다. GOAT / Pro / Max / Team / Provider 플랜에서 동작합니다.

## 결과 읽는 법

사람마다 4개 축(EI·SN·TF·JP)을 따로 판정하고, **얼마나 확신하는지**를 색과 퍼센트로 나눠 보여줍니다.

| 색 | 단계 | 신뢰도 | 뜻 |
|---|---|---|---|
| 진한 초록 | 확실 | 70% 이상 | 여러 발화에서 일관된 근거 |
| 노랑 | 보통 | 50~69% | 패턴은 보이나 반대 근거도 있음 |
| 주황 | 약함 | 25~49% | 단서가 적거나 충돌 → **판단 보류** |
| 회색 | 판단 불가 | 25% 미만 | 근거 없음 → `?` 로 표시 |

- **추정 가능한 축만** 결과에 반영합니다. 예: `E?FP` 처럼 물음표가 섞여 나옵니다.
- **데이터 충분도**가 낮으면 "판단에 약 N% 부족"이라고 알려줍니다.
- 모든 판단에는 대화에서 그대로 인용한 **근거 발화**가 붙습니다.

## 파일 구조

```
server/
  index.js       HTTP 서버 + 정적 파일 + API 엔드포인트
  analyze.js     등장인물 추출 / 인물별 판정 (JSON 파싱·재시도·정규화)
  commandcode.js Command Code Provider API 클라이언트
  prompt.js      인물 추출·판정 프롬프트와 JSON 스키마
  models.js      선택 가능한 모델 목록
  logger.js      로그 기록
public/
  index.html  styles.css  app.js
logs/
  analyze.log    요청별 성공/실패 기록
```

### 엔드포인트

| 경로 | 하는 일 |
|---|---|
| `POST /api/speakers` | 대화에서 등장인물 목록만 추출 |
| `POST /api/analyze-person` | 지정한 한 사람만 판정 |
| `GET /api/models` | 사용 가능한 모델 목록 |

## 판정이 실패할 때

`logs/analyze.log` 에 요청마다 결과가 남습니다. `label` 로 어느 단계인지 구분합니다.

```
{"event":"ok","label":"speakers","ms":5330}
{"event":"ok","label":"person:지훈","ms":15093}
{"event":"error","label":"person:수민","status":524,"message":"..."}
```

- `event: "error"` — `code`, `status`, `message` 로 원인 확인
- `event: "bad_json"` — 모델이 JSON 형식을 어긴 경우. 원본 응답이 `logs/raw-*.txt` 로 저장됩니다.
- `status: 524` — 게이트웨이 시간 초과. 일시적이면 자동 재시도하고, 계속되면 대화를 나누세요.

한 요청의 기본 제한 시간은 120초이고, 5xx·시간 초과·JSON 오류는 자동으로 한 번 재시도합니다
(`ANALYZE_TIMEOUT_MS` 환경변수로 조절).

## 참고

이 결과는 대화 발화 패턴에 대한 통계적 추정이며 심리 검사가 아닙니다.
근거가 약한 축은 판정하지 않고 그대로 표시하지만, 재미와 대화 소재로만 사용하세요.
